# مواصفات تجربة المستخدم — ميزان
## تعليمات التنفيذ التفصيلية للتجربة النظيفة

**الإصدار:** 3.0 · **التاريخ:** 17 يوليو 2026
**المبدأ الحاكم:** شاشة واحدة = مهمة واحدة. كل عنصر لا يخدم المهمة الحالية يُحذف.

---

## الجزء الأول: تشخيص المشاكل في التجربة الحالية (v2)

قبل البناء، هذه هي الأخطاء السبعة التي كسرت التجربة — يجب عدم تكرارها:

### الخطأ 1: ثلاث طبقات تنقّل متنافسة
التجربة الحالية تكدّس: شريط علوي (58px) + قائمة جانبية كاملة (228px) + تقسيم 35/65 داخلهما. النتيجة: منطقة المحتوى الفعلية للوثيقة تنكمش إلى ~50% من الشاشة، والعين لا تعرف أين تنظر.

### الخطأ 2: قائمة جانبية بسبعة عناصر — أربعة منها فارغة
"تحليل العقود" و"مواعيد التقاضي" شاشات «قريباً». عرض ميزات غير موجودة في التنقل الرئيسي يستهلك الثقة وينتهك مبدأ البساطة. المنتج الحقيقي يفعل شيئين: بحث وصياغة.

### الخطأ 3: صندوقا بحث مكرران
شريط بحث في الأعلى + شريط بحث في وسط الشاشة الرئيسية = المستخدم يتساءل: ما الفرق؟ (لا فرق). التكرار = تشويش.

### الخطأ 4: ضجيج تحفيزي في المقدمة
"🔥 5 أيام متتالية" و"وفّرت 47 دقيقة" في الشريط العلوي الدائم تنافس المهمة الأساسية على الانتباه في كل شاشة. المحامي أثناء صياغة إنذار عدلي لا يريد رؤية شارة ألعاب.

### الخطأ 5: التقسيم 35/65 يظهر فجأة
الشاشة الرئيسية بعرض كامل، ثم فجأة تنقسم عند البحث. تغيير البنية الأساسية للشاشة أثناء الاستخدام يكسر النموذج الذهني.

### الخطأ 6: قانون فيتس مُنتهَك
أزرار الإجراءات (حفظ/نسخ/صياغة) مكررة في كل بطاقة نتيجة — 21 زراً في شاشة واحدة. الإجراء يجب أن يظهر عند الحاجة (hover أو تحديد)، لا دائماً.

### الخطأ 7: وثيقة قانونية على خلفية داكنة
المحامي يقرأ ويراجع نصوصاً طويلة. النص الفاتح على الداكن يرهق العين في القراءة الطويلة، ولا يشبه الورق الذي سيُطبع. المحرر يجب أن يكون «ورقة بيضاء» حتى لو كانت الواجهة داكنة.

## الجزء الثاني: البنية الجديدة — ثلاث شاشات فقط

```
┌─────────────────────────────────────────────┐
│  البنية الكاملة للتطبيق:                      │
│                                             │
│  1. الرئيسية  ← نقطة انطلاق واحدة            │
│  2. مساحة العمل ← بحث أو صياغة (تقسيم 35/65) │
│  3. المكتبة   ← كل ما حفظته                  │
│                                             │
│  لا يوجد شيء آخر. نهائياً.                   │
└─────────────────────────────────────────────┘
```

### 2.1 التنقل: شريط أيقونات نحيف (Rail) بدل القائمة الجانبية

**احذف** القائمة الجانبية 228px نهائياً. **استبدلها** بشريط أيقونات:

| الخاصية | القيمة |
|---|---|
| العرض | 64px ثابت، على اليمين |
| المحتوى | 4 أيقونات فقط |
| الأيقونات | 🏠 الرئيسية · 🔍 بحث · ✍️ صياغة · 📁 المكتبة |
| أسفل الشريط | صورة المستخدم (تفتح قائمة: الإعدادات، الاشتراك، خروج) |
| التسمية | tooltip عند hover فقط — لا نص دائم |
| الحالة النشطة | خلفية ذهبية شفافة + خط ذهبي 3px على الحافة اليمنى |

**قاعدة:** الإعدادات والاشتراك والترقية ليست تنقلاً رئيسياً — تختبئ خلف صورة المستخدم.

### 2.2 الشريط العلوي: يظهر فقط في مساحة العمل

- **الشاشة الرئيسية:** لا شريط علوي إطلاقاً. Rail + محتوى. نظافة كاملة.
- **مساحة العمل:** شريط رفيع (48px) يعرض فقط: اسم المستند/الاستعلام + حالة الحفظ + زر تصدير.
- **العدادات التحفيزية** ("وفّرت 45 دقيقة"): تظهر مرة واحدة فقط كإشعار toast عند إنجاز المهمة، ثم تختفي. سجلّها الكامل في صفحة المكتبة، ليس في الشريط الدائم.

## الجزء الثالث: الشاشة الرئيسية — «صفر تشويش»

الغرض الوحيد: إدخال المستخدم في مهمة خلال أقل من 5 ثوانٍ.

### التكوين (من الأعلى للأسفل، كله في وسط الشاشة):

```
┌──────────────────────────────────────────────┐
│ [rail]                                       │
│         مساء الخير، أحمد 👋                   │
│                                              │
│    ┌──────────────────────────────────┐      │
│    │ 🔍 ابحث في القانون العُماني…      │      │  ← صندوق واحد كبير
│    └──────────────────────────────────┘      │
│                                              │
│    ┌───────────────┐  ┌───────────────┐      │
│    │ ✍️ صياغة وثيقة │  │ 📄 آخر مستند   │      │  ← بطاقتان فقط
│    └───────────────┘  └───────────────┘      │
│                                              │
│    آخر نشاطك:                                │
│    · بحث: التزامات صاحب العمل (منذ ساعتين)    │  ← 3 أسطر كحد أقصى
│    · مسودة: عقد عمل البلوشي (أمس)             │
│    · بحث: التحكيم التجاري (منذ يومين)         │
└──────────────────────────────────────────────┘
```

### القواعد الصارمة:
1. **صندوق بحث واحد** — عرض 640px، ارتفاع 56px، في منتصف الشاشة عمودياً وأفقياً. هو البطل.
2. **بطاقتان تحته فقط:** «صياغة وثيقة جديدة» و«متابعة آخر مستند». لا شبكة تصنيفات، لا 8 بطاقات فئات — التصنيفات فلاتر داخل نتائج البحث، ليست تنقلاً.
3. **آخر النشاط: 3 عناصر كحد أقصى** بنص رمادي هادئ. الأرشيف الكامل في المكتبة.
4. **لا إحصائيات، لا شارات، لا صندوق ترقية** في الرئيسية. مؤشر التجربة المجانية: سطر واحد صغير أعلى يمين المحتوى «تجربة مجانية — 10 أيام متبقية» بلون رمادي، يتحول ذهبياً في آخر 3 أيام فقط.
5. التحية بحسب الوقت (صباح/مساء الخير) — لمسة إنسانية واحدة تكفي.

## الجزء الرابع: مساحة العمل — التقسيم 35/65 الثابت

### 4.1 المبدأ: بنية واحدة لا تتغير

بمجرد دخول أي مهمة (بحث أو صياغة)، تفتح «مساحة العمل» بتقسيم ثابت:

```
┌────┬────────────────────────┬───────────────┐
│rail│      المحتوى 65%        │  المساعد 35%   │
│64px│   (النتائج/الوثيقة)     │  (محادثة ذكية) │
│    │                        │               │
│    │   خلفية: ورقة فاتحة     │  خلفية: داكنة  │
└────┴────────────────────────┴───────────────┘
         يسار                      يمين
```

**قاعدة اتجاه RTL:** المساعد على **اليمين** (يُقرأ أولاً — هو نقطة البداية)، والمخرَج على **اليسار**. العين العربية تمسح من اليمين: تسأل يميناً ← ترى النتيجة يساراً. 

**قاعدة الثبات:** هذا التقسيم لا يتغير أبداً داخل مساحة العمل. البحث والصياغة نفس البنية تماماً — يتغير المحتوى فقط. المستخدم يتعلم النموذج مرة واحدة.

### 4.2 لوحة المساعد (35% يمين) — المواصفات

| عنصر | المواصفة |
|---|---|
| الخلفية | داكنة `#131724` — تمييز بصري عن منطقة المخرج |
| الرأس | 48px: أيقونة + «مساعد ميزان» + حالة (يفكر/جاهز) |
| جسم المحادثة | فقاعات رسائل، AI يمين بلون سطحي، المستخدم بذهبي شفاف |
| أسئلة المعالج | سؤال واحد فقط ظاهر في كل مرة، مع زر «تخطّي» |
| اختيارات سريعة | حبوب (chips) قابلة للنقر تحت سؤال AI — الكتابة اختيارية دائماً |
| شريط التقدم | خط رفيع 3px أعلى اللوحة يمتلئ ذهبياً — بدون تسميات مراحل مفصلة |
| صندوق الإدخال | ثابت أسفل، سطران، Enter يرسل |

**قاعدة الصوت الواحد:** المساعد لا يعرض أبداً أكثر من سؤال واحد معلّق. لا قوائم أسئلة، لا نماذج متعددة الحقول داخل المحادثة.

### 4.3 لوحة المحتوى (65% يسار) — وضع البحث

| عنصر | المواصفة |
|---|---|
| الخلفية | داكنة (نتائج البحث بطاقات — ليست وثيقة للقراءة الطويلة) |
| أعلى اللوحة | سطر واحد: «7 نتائج · [فلاتر منسدلة]» — الفلاتر قائمة منسدلة وليست صف أزرار |
| ملخص AI | بطاقة واحدة أعلى النتائج، بحد أزرق، مع مراجع منقورة [م.44] تقفز للنتيجة |
| بطاقة النتيجة | المصدر + المادة + شارة الحالة (نافذ ✓ / تحت التحديث ⚠) + النص مع تظليل ذهبي |
| **الإجراءات** | **تظهر فقط عند hover** على البطاقة: حفظ · نسخ · صياغة ← (يزيل 21 زراً دائماً) |
| النقر على نتيجة | يفتحها موسّعة في نفس المكان (accordion) — لا صفحة جديدة |

### 4.4 لوحة المحتوى (65% يسار) — وضع الصياغة

| عنصر | المواصفة |
|---|---|
| **الخلفية** | **ورقة فاتحة `#faf8f4` بنص داكن `#1a1d26`** — الاستثناء الوحيد للثيم الداكن |
| الورقة | عرض أقصى 720px، ظل خفيف، هوامش 48px — تحاكي A4 |
| قبل التوليد | حالة فارغة: أيقونة + «أجب على أسئلة المساعد يميناً وستتشكل وثيقتك هنا» |
| أثناء التوليد | **الوثيقة تُبنى قسماً قسماً مباشرةً مع كل إجابة** — البند يظهر فور الإجابة عنه (هذا أهم عنصر «سحري» في التجربة، يستبدل شريط الانتظار) |
| المتغيرات الناقصة | `[اسم الموظف؟]` بخلفية ذهبية فاتحة وحد منقّط — النقر يفتح إدخالاً **مضمّناً في مكانه** (وليس نافذة منبثقة) |
| متغير مُعبّأ | يتحول لنص عادي بوميض أخضر لثانية |
| عداد النواقص | شارة صغيرة في شريط المستند: «3 حقول ناقصة» — النقر يقفز للحقل التالي |
| المصادر | ليست صندوقاً منفصلاً — أيقونة § صغيرة نهاية كل بند، hover تعرض المادة القانونية، والقائمة الكاملة خلف زر «المصادر (5)» في شريط المستند |

### 4.5 شريط المستند (فوق الورقة، 48px)

من اليمين لليسار: اسم الملف (قابل للتحرير) · حالة الحفظ التلقائي («تم الحفظ ✓» رمادي صغير) · عداد النواقص · زر المصادر · **زر تصدير ذهبي** (الإجراء الأساسي الوحيد الملوّن).

### 4.6 الإجراءات على النص المحدد

بدل شريط «إجراءات سريعة» دائم أسفل الشاشة (ضجيج)، **تحديد أي نص في الوثيقة يُظهر قائمة عائمة صغيرة** فوق التحديد: أعد الصياغة · اختصر · ابحث عن سند · اشرح. النتيجة تعود عبر المساعد يميناً. هذا يربط اللوحتين ويُبقي الورقة نظيفة.

## الجزء الخامس: التدفقات الحرجة

### 5.1 من البحث إلى الصياغة (اللحظة الأهم في المنتج)
1. المستخدم موسّع نتيجة (المادة 44 مثلاً)
2. عند hover يظهر «صياغة ←»
3. النقر: **نفس مساحة العمل تتحول** — لوحة المحتوى تنتقل من النتائج إلى الورقة الفارغة، والمساعد يقول: «سنصيغ استناداً للمادة 44 من قانون العمل. ما نوع الوثيقة؟» مع حبوب اختيار
4. **لا إعادة تحميل، لا شاشة وسيطة، لا فقدان سياق.** البحث يبقى متاحاً بزر «→ النتائج» في شريط المستند

### 5.2 اختيار نوع الوثيقة (بداية الصياغة من الرئيسية)
- بطاقة «صياغة وثيقة» في الرئيسية تفتح مساحة العمل والمساعد يعرض **6 أنواع كحبوب**: عقد عمل · إيجار · إنذار عدلي · صحيفة دعوى · NDA · مقاولة، مع صندوق «أو صف ما تحتاجه بكلماتك…»
- لا صفحة كتالوج منفصلة لأنواع الوثائق

### 5.3 أسلوب المستند
سؤال أخير قبل التوليد، 3 حبوب: حازم ومباشر · ودي/تسوية · مفصّل بالأسانيد. افتراضي محدد مسبقاً بحسب نوع الوثيقة (إنذار→حازم، تسوية→ودي). المستخدم يضغط «توليد» مباشرة إن لم يهتم.

### 5.4 التصدير
نافذة واحدة، 3 خيارات كبيرة: Word قابل للتعديل · PDF مسودة · PDF رسمي مع ختم. خيارات الترويسة والتذييل تُحفظ من آخر مرة — لا يعيد ضبطها كل مرة.

## الجزء السادس: صفحة المكتبة

- شبكة بطاقات موحدة: مسودات + عمليات بحث محفوظة معاً، فلترة بحبتين أعلى الصفحة (الكل · مسودات · أبحاث)
- ترتيب افتراضي: الأحدث أولاً
- بطاقة = أيقونة + اسم + تاريخ + شارة النوع. النقر يفتح مساحة العمل بالحالة المحفوظة كاملة (بما فيها محادثة المساعد)
- هنا فقط يظهر ملخص الإنجاز أعلى الصفحة: «وفّرت 4.3 ساعة هذا الشهر» — سطر واحد هادئ

## الجزء السابع: نظام التصميم المُحدَّث

### الألوان
| الرمز | القيمة | الاستخدام |
|---|---|---|
| `--bg` | `#0b0d14` | خلفية عامة |
| `--surface` | `#131724` | لوحة المساعد، البطاقات |
| `--paper` | `#faf8f4` | **ورقة المستند فقط** |
| `--ink` | `#1a1d26` | نص الوثيقة على الورقة |
| `--gold` | `#c9a84c` | الإجراء الأساسي + الحالة النشطة فقط |
| `--ok` / `--warn` | `#2a8055` / `#b8760f` | شارات الحالة فقط |

**قاعدة الذهبي:** عنصر ذهبي واحد أساسي كحد أقصى في كل شاشة (زر التصدير في الصياغة، زر البحث في الرئيسية). الذهبي عملة — الإكثار منه يُفقده قيمته.

### الخط
Cairo. الوثيقة على الورقة: 15px/سطر 2.2. الواجهة: 13px. لا يقل أي نص عن 11px.

### الحركة
- انتقالات 180ms فقط، لا حركات استعراضية
- استثناءان مسموحان: بناء الوثيقة قسماً قسماً (fade-in 300ms لكل بند)، ووميض النجاح الأخضر عند تعبئة متغير

### إفراغ الشاشات (Empty states)
كل حالة فارغة = أيقونة + جملة واحدة + إجراء واحد. لا نصوص شرح طويلة.

## مقياس النجاح
اختبار «الخمس ثوانٍ»: مستخدم جديد يفتح أي شاشة — إن لم يعرف خلال 5 ثوانٍ (أ) أين هو، (ب) ماذا يفعل تالياً، (ج) أين الإجراء الأساسي — فالشاشة فاشلة وتُعاد.
